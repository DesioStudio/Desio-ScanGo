## 为什么做这个

### 缘起：小时候的便利店梦想

小时候第一次在便利店看到扫码收银时，我觉得那是一件非常神奇的事——商品条码往扫描设备前一放，电脑就能认出商品、显示价格、完成整个收银流程。那时候我总想：如果自己也有一家便利店，能像真正的收银员一样扫码、结算，一定很有意思。

后来我真的动手搭了一个：找了一套免费开源的收银系统，又找到一款能让手机连电脑当扫码设备的工具，于是家里跑起了这样一条链路——手机扫条码 → 结果传到电脑 → 收银系统识别商品 → 完整还原便利店收银。那一刻我第一次真切感受到，**普通设备通过软件组合，可以变成一个完整的商业系统**。

几年后，那款手机扫码软件逐渐停止维护，再也用不上了。我重新去找替代品，却发现：很多软件只能让手机自己扫完就结束，很多工具绑死特定硬件，简单、开源、能真正替代扫码枪的方案少之又少。

于是我想：为什么不自己重新做一个？

> 完整故事见 [为什么做 Desio ScanGo](docs/story.md)。

### 抛开情结，它解决的是什么

想让电脑"认条码"，通常只有两条路，两条都不太顺：

**买一把专用扫码枪。** 几百块的硬件，占一个 USB 口，线材碍事，坏了要重买。而且绝大多数扫码枪本质就是一个键盘——插上去之后它做的事，和你用键盘把那串数字敲进去没有任何区别。

**在手机上扫，然后手动发到电脑。** 微信传一下、邮件发一下、拷贝到剪贴板再切窗口粘贴……扫十条就烦了。

既然扫码枪本质上就是个键盘，那这件事完全可以用**你口袋里那台带摄像头的手机**来做。Desio ScanGo 就是这么想的：手机负责看，电脑负责收，中间只走你自己的局域网，不经任何服务器。

手机端是一个网页，不是 App——不用装、不用更新、不用申请权限到应用商店，扫个码就能用，关掉就没了。

## 适合什么场景

| 场景 | 怎么用 |
| --- | --- |
| 仓库 / 库存盘点 | 光标点到 Excel 单元格，拿手机对着货架挨个扫，开「扫码后按 Enter」自动换行 |
| 小店进销存 | 光标点到 ERP 的搜索框，扫商品条码直接带出商品 |
| 图书 / 档案 / 固定资产 | 批量录入编号，比手敲快且不会敲错 |
| 收发货核对 | 边扫边看桌面端历史列表，核对扫了多少条、有没有漏 |
| 开发与测试 | 需要条码内容填表单时，不用手打一长串数字 |

**也说说不适合什么**，免得你白折腾：

- 工业级流水线高频扫描——手机的连续扫描速度和耐用性不如专业设备
- 需要离线防护、防尘防摔的仓库现场
- 一次要上百人同时扫的场合——项目目前没有做并发和权限体系

## 和硬件扫码枪比怎么样

| | Desio ScanGo | 硬件扫码枪 |
| --- | --- | --- |
| 成本 | 有手机就零成本 | 几百元起 |
| 部署 | 扫码即用，不用装驱动 | 插 USB、可能要装驱动或配置 |
| 多设备 | 多台手机可以同时连一台电脑 | 通常一对一 |
| 移动性 | 手机走到哪扫到哪，不受线长限制 | 受线缆长度约束 |
| 维护 | 软件更新即可 | 硬件损坏要换 |
| 离线 | 依赖本地局域网，不需要外网 | 完全离线 |
| 耐用性 | 取决于你的手机 | 工业级更耐摔 |

一句话概括：**它替换的是「偶尔要扫码录入」这类需求**，不是把专业设备淘汰掉。

## 功能特性

- **零安装接入**：手机无需装 App，扫桌面端二维码即可开始扫码
- **实时回传**：WebSocket 长连接，扫码结果毫秒级到达电脑
- **自动键入**：结果可自动输入到当前焦点窗口，可选每次扫完自动按 Enter
- **多设备同时连接**：几个人可以同时扫同一台电脑，每条记录标注来源设备
- **扫码历史**：服务端保留最近 50 条记录，界面显示最近 20 条，含条码值、格式、时间
- **识别反馈**：手机端扫码成功有提示音与震动，提示音可开关
- **HTTPS 支持**：内置自签证书方案，让 iOS Safari 在局域网下也能调用摄像头
- **中英双语**：界面默认中文，一键切换英文；应用菜单同为中文
- **纯本地**：数据只在你的手机和电脑之间传输，无云端、无遥测、无账号

## 支持的条码格式

当前版本启用的解码格式：

| 格式 | 常见用途 |
| --- | --- |
| EAN-13 | 商品条码（国内绝大多数包装） |
| EAN-8 | 小包装商品 |
| UPC-A / UPC-E | 北美商品条码 |
| Code 128 | 物流、仓储、快递单 |
| Code 39 | 工业、资产管理标签 |
| QR Code | 二维码 |

解码由 [ZXing](https://github.com/zxing-js/library) 完成，全部在手机浏览器本地执行。需要 ITF、Codabar、Data Matrix、PDF417 等更多格式的话，改一行解码配置即可（见 [路线图](#路线图)）。

## 工作原理

```text
手机摄像头 → 浏览器本地解码(ZXing) → WebSocket 回传 → 桌面端 → 键盘输入 / 历史列表
```

1. 桌面端在本机启动一个局域网服务（HTTP 或 HTTPS + WebSocket），监听 `0.0.0.0`
2. 桌面端把服务地址编码成二维码显示在窗口里
3. 手机扫码打开网页，浏览器申请摄像头权限并开始解码
4. 每扫到一条，通过 WebSocket 发回桌面端
5. 桌面端按设置决定：是否键入、是否追加回车，并写入历史列表

**扫码服务的端口是随机分配的**（每次启动都可能不同）。所以不要保存旧链接，每次用桌面端上显示的那个二维码。

技术栈：

| 层 | 技术 |
| --- | --- |
| 桌面端外壳 | Electron |
| 桌面端界面 | React + Vite |
| 手机端扫码页 | React + Vite + ZXing |
| 局域网服务 | Express + ws |
| 键盘输入模拟 | Windows `WScript.Shell.SendKeys` |

## 快速开始

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows（键盘输入模拟基于 Windows） |
| Node.js | 20 或更高 |
| 网络 | 手机与电脑在**同一个 WiFi / 局域网** |
| 证书 | 需要 openssl（生成 HTTPS 证书用） |

### 安装并启动

```bash
npm install
npm run dev:cert   # 生成 HTTPS 证书（换 WiFi 或 IP 变化后要重跑）
npm run dev
```

桌面端窗口会自动打开，右上角显示「运行中」，右侧是配对二维码。

启动的是两个服务：

| 服务 | 默认地址 | 说明 |
| --- | --- | --- |
| 手机端页面 | `https://<本机IP>:5173` | Vite 开发服务器 |
| 桌面端扫码服务 | `https://<本机IP>:<随机端口>` | 二维码里指向的就是它 |

## 桌面端怎么用

界面分四块：

- **顶部**：运行状态、服务地址、语言切换
- **配对区**：二维码 + 服务地址。手机扫这里
- **设备与键盘**：已连接的手机列表；两个开关——
  - `将扫码结果输入到当前窗口`：关闭后扫码只记录不打字
  - `每次扫码后按 Enter`：扫完自动回车，适合 Excel 逐行录入
- **扫码记录**：最近 50 条，含条码值、格式、时间

**键盘输入会打到当时有焦点的窗口。** 正式用法是先把光标点到目标输入框（Excel 单元格、ERP 搜索框等），再用手机扫。不想自动输入就把开关关掉，记录仍会保留。

## iPhone 必读：装一次证书

iOS Safari 有一条硬性规定：**只有 `https://` 或 `localhost` 下的页面才允许调用摄像头**。局域网 IP（`http://192.168.x.x`）属于非安全来源，`navigator.mediaDevices` 直接是 undefined，扫码功能根本不会启动。

Android Chrome 可以用 flag 临时放行，iOS 没有这个开关，所以只能走 HTTPS + 自签证书。这也是上面要先跑 `npm run dev:cert` 的原因。

证书只需安装一次，之后长期有效（有效期 825 天，这是 iOS 对服务器证书的硬性上限）。

### 安装步骤

**1. 下载证书**

用 iPhone 的 Safari 访问（端口看桌面端二维码上显示的那个，每次随机）：

```text
https://192.168.x.x:<端口>/ca.pem
```

Safari 会提示「无法验证服务器身份」，点「详细信息」→「访问此网站」。

**2. 安装描述文件**

弹出安装提示后点「允许」，按引导完成安装。

**3. 手动开启信任（最容易漏的一步）**

```text
设置 → 通用 → VPN与设备管理 → 安装描述文件
设置 → 通用 → 关于本机 → 证书信任设置 → 打开 "Desio ScanGo Dev CA" 开关
```

**只有第 3 步做完，Safari 才会真正信任这张证书。** 装了描述文件但没开信任开关，访问时依然会被拒绝。

### IP 变了怎么办

证书里写死了签发时的局域网 IP。换 WiFi、路由器重新分配地址之后，需要重新签发：

```bash
npm run dev:cert
```

然后重启 dev，iPhone 上重新装一次新证书。

## Android 说明

Android Chrome 有两个选择：

- **推荐**：跟 iOS 一样走 HTTPS，访问 `https://<本机IP>:<端口>/ca.pem` 下载证书安装即可
- **临时方案**：地址栏打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`，填入 `http://<本机IP>:5173`，重启浏览器

Android 上扫码成功会同时震动并播放提示音；iPhone 不支持震动接口，只有提示音。

## 常见问题

**手机上打不开二维码里的地址**

先确认手机和电脑在同一个 WiFi，且 IP 前三位一致。然后确认电脑防火墙没有拦掉 Node.js / Electron（Windows 公用网络下默认可能拦截）。路由器开启了「AP 隔离」或连的是访客网络的话，设备之间也互不可见。

**页面打开了，但点开始扫码没反应**

十有八九是没走 HTTPS，或者证书没开信任。页面上会直接提示「当前不是安全来源，浏览器已禁用摄像头」，按上面的步骤装证书即可。

**扫码结果打到了聊天框 / 别的地方**

键盘输入会打到**当时有焦点的窗口**。正式用法是先把光标点到目标输入框再扫。不想自动输入的话，在桌面端取消勾选「将扫码结果输入到当前窗口」，记录仍会保留在列表里。

**扫码服务端口每次都不一样**

这是设计如此（端口随机分配）。重启后请用桌面端上最新的二维码，别存旧链接。

**没有 openssl 怎么办**

`npm run dev:cert` 依赖 openssl。Windows 上装 Git for Windows 后会自带（在 `Git\mingw64\bin\openssl.exe`）。没有的话整个项目会自动回落到 HTTP，功能不受影响，只是 iPhone 无法调用摄像头。

**杀毒软件报警**

键盘输入模拟用的是 Windows 自带的 `WScript.Shell.SendKeys`，和扫码枪的原理一致，不是键盘记录器（项目不记录任何按键）。部分安全软件对这类 API 比较敏感，加白名单即可。

## 分发给其他人

| 对象 | 怎么用 | 状态 |
| --- | --- | --- |
| 扫码的手机 | 无需安装任何 App，扫桌面端二维码即用 | 完全可用 |
| 想在自己电脑上跑的人 | 按[部署指南](docs/deployment.md)在**本机**装依赖并生成证书 | 推荐方式 |
| 想要双击安装包的人 | `npm run package` 生成 exe | 有限制，见下 |

### 为什么推荐源码运行而不是发安装包

HTTPS 证书里绑定的是签发时的局域网 IP。每台电脑的 IP 不同，所以证书必须由使用者**在自己机器上现场生成**，别人代劳生成好再拷贝过去是无效的。

源码运行方式下，`npm run dev:cert` 会按当前机器的 IP 签发证书，iPhone 完全可用。完整步骤见 [docs/deployment.md](docs/deployment.md)（[English](docs/deployment.en.md)），照做约十分钟。

> **已知限制**：`npm run package` 打出来的安装包目前不带证书，会以 HTTP 运行，因此**打包版在 iPhone 上无法调用摄像头**。要让它也支持 iOS，需要程序在首次启动时按当前局域网 IP 自动生成证书（尚未实现）。在那之前，请把部署指南发给使用者。

## 更远的想法

扫码只是起点。这个项目真正想探索的是：**如何让我们手中的普通设备，通过软件获得新的能力。**

沿着这个方向，手机还可以成为：

- OCR 文字输入设备
- 电脑的无线摄像头
- AI 视觉采集终端
- 更广义地说：电脑的无线扩展设备

很多年前我觉得扫码枪是一种神奇的专业设备，后来发现真正神奇的不是扫码枪本身，而是软件可以重新定义普通设备的能力。如果你对这些方向也有兴趣，欢迎来聊。

## 安全与隐私

**隐私方面**：摄像头画面只在手机本地解码，不录制、不存储；扫码数据只在你的手机和你的电脑之间通过局域网传输，没有云端中转；项目不收集任何统计数据，没有遥测，没有账号体系。

**安全方面**：Desio ScanGo 面向**可信的局域网**使用。当前版本只要设备能打开配对链接就可以发送扫码结果，没有做配对令牌或设备审批——在公共网络等不可信环境中，同一网络内的人可以向你的电脑注入伪造条码。完整威胁模型与漏洞报告方式见 [SECURITY.md](SECURITY.md)（[English](SECURITY.en.md)）。

证书仅用于本地开发调试，`certs/` 目录（含私钥）永远不会提交到仓库，请勿用于生产环境对外服务。
